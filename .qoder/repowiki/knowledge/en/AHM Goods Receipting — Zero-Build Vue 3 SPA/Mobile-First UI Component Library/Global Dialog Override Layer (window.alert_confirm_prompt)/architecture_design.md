Two-file split with clear dependency direction: `useDialog.js` owns the global state singleton (`window.__VUE_CUSTOM_DIALOG_STATE__`) — a set of Vue `ref`s plus an in-flight `resolvePromise` — and exposes two entry points: `useDialog()` for reactive consumption by components and `initWindowOverrides()` which rebinds `window.alert`/`confirm`/`prompt` to call `openDialog`, returning a Promise resolved via `handleAction`. `CustomDialog.vue` is a pure consumer that imports `useDialog`, watches `isOpen`+`type` to auto-focus the prompt input, and renders the overlay/card UI. State flows one-way: callers → `openDialog` → shared refs → `<CustomDialog>` template; user actions flow back through `handleAction` resolving the pending promise. The README documents the design rationale (global context mirroring, thread promisification, Teleport placement) even though the current implementation mounts into the component tree rather than using Teleport.
