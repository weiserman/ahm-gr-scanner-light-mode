Two cooperating files with a clear dependency direction: `serviceWorker/serviceWorker.js` is the public bridge consumed by Vue code (e.g. `src/main.js`, `src/main.sfc.js`) and exports three functions — `registerServiceWorker(workerScriptPath)` (wraps `navigator.serviceWorker.register` on `window.load`, then resolves `.ready`), `sendWorkerMessage(payload)` (uses `controller.postMessage` only when a controller exists), and `listenForWorkerMessages(cb)` (attaches a `'message'` listener). The standalone file `sw.js` is NOT the actual SW script; it is a runtime helper imported from application code that calls `syncServiceWorkerState()` to either register `mock-sw.js` (when `store.config.useDummyData` is true) or unregister all existing registrations and reload the page. The real worker script lives at `/public/sw.js` (referenced by the README) and communicates back via the same `postMessage` channel. There is no build manifest inside this scope — registration paths are passed in as strings so Vite (`/sw.js`) and SFC loader (`/public/sw.js`) can differ.
